# redis-patterns-lab — правила для ассистента

- Публичный репозиторий. Никаких корпоративных имён: сервисов, таблиц, пакетов, тикетов и названий компаний из рабочих проектов. Список запрещённых слов лежит в `.git/info/forbidden-words` и проверяется хуками `pre-commit` и `commit-msg`.
- Этап 3 учебного плана: Redis не как кэш — ограничение частоты запросов, распределённая блокировка с арендой (сценарий с маркером ограждения отменён), идемпотентность запросов. Этапы 1 и 2 — [caching-lab](https://github.com/olaaa/caching-lab) и [distributed-cache-lab](https://github.com/olaaa/distributed-cache-lab). Темы — по одной за раз, следующая после разбора предыдущей.
- Стек: Java 25, Spring Boot 4.1, WebFlux, R2DBC через `DatabaseClient`, Reactor, Spring Data Redis с клиентом Lettuce. Без JPA и без Redisson.
- Каждый приём — отдельный компонент и отдельный тест `ScenarioN…Test`. У каждого сценария — описание в `docs/scenarios/NN-….md` и файл ручной проверки `http/NN-….http`; при изменении сценария обновлять все три.
- Цитаты в описаниях — на русском, в переводе; названия статей и разделов можно оставлять как есть.
- Тесты поднимают PostgreSQL и Redis в Testcontainers; перед каждым тестом база Redis очищается. Время приложения двигает `MutableClock`, без `sleep`. Срок жизни ключей считают часы самого Redis.
- Стиль: многострочные комментарии одним блоком `/* */`, фигурные скобки у тел `if`/`for`/`while`, говорящие имена.
- Ветка `main`. Коммит и пуш — по окончании задачи, `git add` по именам файлов, перед пушем `git fetch`.
